# Agent 岗位面试技术知识库

> 用途：为面试准备模块提供经过审核的技术原理证据。本文只能支撑技术解释，不能证明候选人实际做过某项工作。

## Agent 与 LangGraph

现代 Agent 不等于一次 Prompt 调用。一个可控 Agent 通常包含状态、规划、工具调用、条件路由、失败处理、持久化与人工确认。LangGraph 用显式状态图表达节点和边，适合有固定业务边界、需要暂停恢复和审计的流程。开放式 ReAct 更适合工具选择不确定的局部任务；高风险外发动作仍应由确定性策略和人工审批控制。

LangGraph checkpointer 保存图状态和下一执行位置。恢复时必须使用稳定的 thread_id，并确保写库节点有业务幂等键。checkpoint 解决图状态恢复，不自动解决数据库事务、外部 API 幂等和跨租户权限问题。

## RAG 检索链路

RAG 的典型链路是文档解析、语义切分、Embedding、索引、查询改写、混合召回、重排、上下文构造、带引用生成和事实校验。BM25 擅长匹配 FastAPI、Redis、MCP 等精确术语；向量检索擅长处理“智能体研发”和“Agent 开发”等语义近似；RRF 可以按不同通道的名次融合结果，避免直接比较不可校准的原始分数。

二阶段排序通常先召回 Top20 或 Top30，再用 Cross-Encoder/Reranker 对 query-document 对直接打分，最后保留 TopK 证据。评测需要区分召回失败、重排失败和生成失败，常见指标包括 Recall@K、MRR、nDCG、引用正确率、证据支持率与检索延迟。

## Chunk 策略

Chunk 不应只依赖固定字符长度。结构化简历适合按教育、项目、实习、技能等字段切分；JD 适合按岗位职责、任职要求、加分项等字段切分；PDF 原文需要处理断行、页眉页脚、列表、表格和跨页标题。超长语义段再使用滑动窗口，保留页码、章节、来源和版本等 metadata。

短 chunk 有利于精准召回，但容易丢失上下文；长 chunk 保留上下文，却会稀释相关信息并增加 token 成本；过大的 overlap 会造成重复索引和重复召回。参数应通过带噪声评测集和失败样本决定，而不是凭经验固定。

## FastAPI 并发与后台任务

FastAPI 的 async 主要提升 IO 等待场景的并发利用率，不会让 CPU 密集任务自动并行。短 IO 请求可以在 async 路由内 await；长耗时 LLM、PDF、Embedding 或浏览器任务适合写入外部队列，由多个 worker 消费。CPU 密集任务可以使用进程池、独立服务或底层并行库。

数据库 Session 不应跨并发任务共享。接口创建任务后返回 run_id，worker 独立打开事务；状态、heartbeat、重试次数、错误和结果写入持久化存储。限流、连接池、幂等、超时、取消、优雅 drain 和积压监控共同决定系统能否稳定并发。

## SQLite、向量库与 Redis

SQLite 适合单机、中小规模和开发阶段的权威业务存储，可以保存 Profile、JD、chunk、metadata、embedding、trace 和审批记录。它的主要边界是高并发写入、横向扩展和高可用。规模提升后可以迁移到 PostgreSQL，并根据检索规模选择 pgvector、Qdrant、Milvus 等向量能力。

向量库负责近邻召回，不应成为唯一业务真相。原文、版本、租户、来源和审计信息应保存在权威业务库；向量索引使用稳定 chunk_uid，可从业务库重建。Redis 适合队列、分布式锁、短期状态、限流和 heartbeat，但关键结果仍需落入持久化数据库。

## LLM 输出治理

减少模型错误需要组合使用结构化输出、Schema 校验、RAG 证据约束、来源权限、引用校验、有限 repair、评测门禁和人工确认。Prompt injection 防护应把外部 JD、PDF 和网页内容视为不可信数据，剥离其中的指令语义；工具权限、租户边界和审批不能交给 Prompt 自觉遵守。

“检索到了文本”不等于“文本支持结论”。JD 只能证明岗位要求，不能证明候选人会；面经只能提供问题线索，不能证明公司固定题库；技术文档只能解释原理，不能证明候选人有生产经验。生成结果应把每个关键 claim 绑定到允许支撑它的来源。
